# Code audit, October 2026: what makes the next game expensive

Audit of `main` at `ee8c0de` (2026-10-15), plus the open branch
`muramasa-en` (4 commits: NPK3 archives, Squirrel scripts,
`convert-nss --english`). Every other game branch (`xuse`, `nitroplus`,
`django`, `oretsuba`, `gui`) is already merged into `origin/main`.
The engine (CONscripter) is in scope: engine steps are listed with the
converter's.

Goal: make games 5 to 50, and engines 4 to 20, cheap to add.
Findings are ranked by payoff for that, not by tidiness. Each one gives
the location, the problem, the cost today, a fix, its size (S < half a
day, M about a day, L several) and the risk to the existing games.

Checks run for this audit: `cargo test` (197 tests, all pass),
`cargo clippy --all-targets` (5 warnings, §9), and a `--dry-run` of all
four games into `out/audit-<game>-dry` (the baselines for §8). The
Xuse, Muramasa and Django dry runs are byte-identical from run to run.
The MAGES one is not (finding 4).

## 4. IR fitness

Engine-neutral (screen-level verbs any VN needs): `Label`, `Jump`,
`Gosub`, `Return`, `Arith`, `If`, `Background`, `ClearSprites`,
`Sprites`, `SpriteFilters`, `SpriteOpacity`, `SpriteMove`, `SpriteZoom`,
`SpriteMotion`, `AnimatedSprite`, `BeginTransition`/`EndTransition`,
`ScreenFilter`, `ScreenEffect`, `Flash`, `ScreenFlash`, `ScreenFade`,
`Text`, `SetWindow`, `HideTextWindow`, `InstantText`, `BgmPlay`,
`BgmStop`, `SePlay`, `SeStop`, `SeFadeIn`, `SeFadeOut`, `SoundVolume`,
`Wait`, `Pause`, `ClickWait`, `Movie`, `SceneMovie`, `Choice`,
`Chapter`, `ReturnToTitle`, `IfSwitch`, `Unsupported`.

Carrying one engine's semantics:

| Op / type | Whose | Problem for a new engine |
|---|---|---|
| `MoveEase { ease: u8, exponent }` | MAGES' curve table | `ease` is an index into MAGES' list (`conv-cons/src/ease.rs`). A new engine with other curves must map onto it or add numbers. Make it `enum Ease` (linear, in, out, in-out × power) |
| `Progress { bit }` (0-31), `CgSeen { number }` (≤ 9 × 64), `UnlockScene { scene }` | Xuse's bit fields | Fixed sizes from one game. Nitroplus uses named flags instead. Fine as global counters, but the limits belong in the allocation table |
| `Overlay`, `Noise`, `NoiseFadeIn`, `Animation`, `SpriteInFront` | Xuse's objects (0x55, 0x8c, 0x7a) | One of each, at fixed sprites (59-61). A second engine with two overlays can't use them. Leave them; a new engine uses `Sprites` layers |
| `TextLink`, `ReturnToRoot`, link scenes | 最果てのイマ's hyperlinks | Neutral in shape; 400 lines of emit and `menu::scene_stack` serve only them. Fine, but keep them in their own module (§2) |
| `SpriteTurn`, `TilePuzzle` | One scene each | Fine: one-offs belong in the IR as boxed variants, as done |

**Extension point.** A new feature is a new `Op` variant at the end of
the enum (CLAUDE.md's rule) plus an arm in `emit`. That is clear, but
both files are the hottest in the repo (finding 5). After the split
the extension point is "add `ir/<family>.rs` items and one
`ops/<family>.rs` module". There is no raw-NScripter escape hatch, and
there shouldn't be one: it would let game rules into the output.

**Two menu families** (finding 7): `Script` has the classic screens
(`save_menu`, `backlog`, `settings`, `extras`: Xuse, MAGES) and the
picture screens (`save_grid`, `line_log`, `picture_settings`,
`picture_extras`, `command_menu`: Nitroplus), about 3,000 lines of
conv-cons each. Merging them would change two games' screens and is
not worth it now. Instead: `docs/new-game.md` step 7 says which to
start from (picture family for a game with drawn screens, which most
are; classic for a game that needs a designed one), and that a third
family needs the user's yes.

plus constants in 15 modules, and each engine places its flags by
reading it. Ranges in use (NScripter `%`):

| Range | Owner |
|---|---|
| %9, %100-%119, %130-%192 | conv-cons scratch and menus (`menu.rs`, `lib.rs`, `picture_gallery.rs`, `replay.rs` %152-%160) |

| %190-%289 | the tile puzzle (`puzzle.rs`) **and** `menu::SCENE_FLOOR` %190, `SCENE_SHIFT` %191, `SCENE_TARGET` %192 (exclusive by game: puzzle is Muramasa's, the scene stack Xuse's) |
| %150, %151 | `menu::SCENE_DEPTH`/`SCENE_MAX_DEPTH` (Xuse) **and** `picture_replay::REPLAYING`/`menu::NO_SAVE` (Nitroplus): exclusive by family |
| %290-%799 | NSS story locals |
| %800-%969 | NSS `#` globals (Muramasa uses all 170) |
| %900-%912 | **classic menu globals** (`PAGE`, `NEWEST`, volumes %902-%906, `TEXT_MS` %907, `SKIP_UNREAD` %908, `SETTINGS_SET` %909, %910-%911) and `DELETED_BASE` %910+n |
| %970+ | voice switches (`VOICE_OFF_BASE`) |
| %1200-%1662 | MAGES scene-read flags |
| %2000-%2964 | links, CGs, movies (%2800), scene carry, switches, sliders (%2922), pairs (%2930), title |

**Live bug (Muramasa).** NSS globals 100-112 land on %900-%912. In
`out/audit-muramasa-dry/0.txt`: `%907` is the text speed in all 38,401
`setwindow3` lines and also the CG flag `#bg006_小光の家_03b`
(`mov %907,1` at line 446,261). Seeing that background sets the text
speed to 1 ms a character, and the settings' speed slider marks the CG
as seen. `%900` is the save grid's page (`mov %900,1` when it opens)
and the CG flag `#bg004_鄙びた村b_02`, so opening the save screen
unlocks that CG. `%902`, `%905`, `%908`-`%911` are CG flags that the
classic menus would also use (Muramasa doesn't have those menus, so
only `%900` and `%907` misbehave). Django has 14 globals (%800-%813):
not affected. Fix: `GLOBAL_ROOM` 100 (globals %800-%899), the rest
past `GLOBAL_OVERFLOW`. This **changes Muramasa's global flag numbers**,
so CG and replay unlocks in an existing `gloval.sav` move: the user
decides (the build isn't released).

**Sprites.** Fixed slots are documented at `lib.rs:53-92`; screens take
whole ranges between `pushscreen` and `popscreen`, so menu sprites at
850-990 and NSS story sprites up to 962 (`MAX_LAYER` 900 + 62) don't
clash. Sound, but only by convention.

**Switches** (finding 12). `switches.rs` gives each engine a block of
100 indexes (100-199 Xuse, 200-299 MAGES, 300-399 Nitroplus, 400-999
new games), but all 20 switches sit in 0-19 and the blocks are
empty. `MAX_INDEX` 1000 leaves room for 6 more engine blocks, not 20.
`Switch` is a shared IR enum anyway, so the blocks don't map to
ownership. Replacement: the next free index, whoever adds it; the
existing test (`each_switch_has_its_own_index_and_flag`) catches
duplicates at merge time. Doc-only change, no number moves.

**Replacement scheme** (finding 1, M):
- `conv-core/src/alloc.rs` (conv-core, because `conv-engines` depends
  only on it): one table of every range, as `(range, owner, family)`
  consts, which the conv-cons modules import instead of their own
  literals. A unit test fails on any overlap not marked
  exclusive between families.
- The engines get their game ranges from it
  (`conv_core::alloc::GAME_LOCALS`, `GAME_GLOBALS`,
  `GAME_GLOBALS_OVERFLOW`) instead of copying numbers.
- `emit` checks at build time that no game `Var` it writes falls in a
  reserved range, and fails the build naming both owners. This would
  have caught the Muramasa bug on the first dry run.
- Pure moves except the Muramasa fix, which goes in its own commit.

Lasts to 50 games: game ranges are per script, not per game, so games
don't compete with each other, only with conv-cons.

## 6. CLI and GUI

- Three subcommands repeat the same seven options (`output`, `font`,
  `title`, `loose`, `dry_run`, `webp`, `audio`; `main.rs:31-127`,
  `mages.rs:31-56`). One `#[command(flatten)] build: BuildArgs`. (S)
- Three copies of the pipeline (finding 2). Proposal: each engine
  exposes `fn build(game: &Path, opts: &BuildOpts) -> Result<Built>` in
  `conv-engines` (`Built` = the `Script`, the notes, and its media jobs:
  audio with loop points, movies). The CLI keeps one
  `build::run(engine, args)` for the shared tail. A new engine is then
  its module plus one `match` arm. (M; byte-identical 0.txt; conflicts
  with `muramasa-en`'s `--english` flag in `convert_nss`, so land after
  it merges or carry the flag over)
- Engine tools (`xarc`, `cd`, `gaf`, `xsa`, `npa`, `nss`) move out of
  `main.rs` into per-engine CLI modules, as `mages.rs` is. (S)
- **Game descriptor** (finding 6). A game is defined in three places:
  `main.rs:850` (exe names), `nitroplus/convert/{muramasa,django}.rs`
  (`Game` tables), `gui/games.py:261` (`GAMES`: markers, command,
  font, size, options). 続・殺戮のジャンゴ has no GUI entry. Proposal:
  a `conscripter-convert detect <dir> --json` subcommand built from
  each engine's `GAMES` list (name, engine, markers, recommended
  options), which the GUI calls instead of keeping its own list (its
  `cli_detect`, `gui/app.py:699`, already prints the same thing). No
  new dependency (JSON by hand or the existing `serde`-free style). (M)
- Cost of a new game today: CLI subcommand or flag, game table,
  `gui/games.py` entry, README row, CLAUDE.md row, PLAN.md row,
  `docs/games/<game>.md`. After: the engine's `GAMES` entry and the doc.

## 7. Engine (CONscripter)

- `ONScripter_cons.cpp` split (§2). (M)
- **Rename `onsyuri`** (the user's request): about 60 places in the
  converter repo (docs, `.github/workflows/release.yml`,
  `crates/conv-cli/build.rs`) and about 350 in the engine (the four
  `src/onsyuri*` folders, CMake lists, `conscripter.html` 82,
  `conscripter_index.py`, ADDITIONS.md, the Android sources). Internal
  names and folders can simply move (`src/onsyuri/` → `src/cons/`,
  `onsyuri_web/` → `cons_web/`, …; one commit per folder, CMake lists
  with them). Five are public interfaces and need a compatibility
  alias, not a plain rename:
  - the web hooks (`onsyuriText`, `onsyuriChoice`, `onsyuriOverlay`,
    `onsyuriBacklog`, `onsyuriSprites`, `onsyuriVoice`,
    `onsyuriPosition`, `onsyuriMode`, `onsyuriWindow`): chimimouryou
    calls them. Add `consText` etc. and keep the old names;
  - `onsyuri_index.json` and the `<meta onsyuri_index>`/`onsyuri_js`
    tags: published game folders have them. Read both names;
  - the IndexedDB save path `/onsyuri_save/<title>`: renaming it
    orphans every web save. Keep it, or copy on first start;
  - emscripten `EXPORT_NAME=onsyuri`: pages call `onsyuri(m)`. Export
    both;
  - the Android package id (`com.yuri.onscripter`): changing it makes
    a new app beside the old one, with its saves left behind.
  (M; risk: web saves if the save path moves)
- Upstream code: of 93 files in `src/onsyuri`, only
  `ONScripter_cons.cpp` is wholly ours; the rest is the ONScripter-Yuri
  base with our edits. A rename makes merges from upstream harder; the
  engine has no upstream remote, so that cost is small.
- Engine work the converter now emulates in script, worth moving per
  CLAUDE.md's "engine-native state": the settings switches' off-flags
  (`switches.rs`, global variables per switch, 3 ranges), the
  confirmations' on/off reads, the save menus' page and newest-slot
  globals. Each is a candidate for engine-kept settings, which would
  also free the variable ranges of finding 1. List only; no step
  proposed until a game needs it.

## 8. Tests and verification

`cargo test`: 197 tests. conv-cons 94 (57 in `lib.rs`; none in
`button_screen`, `movies`, `picture_gallery`, `picture_sound`,
`picture_extras`, `picture_replay`, `replay`, `extras`,
`choice_plates`); conv-engines 101 (nitroplus convert 25 with a fake
asset source, nss 12, xuse convert 18, cd 9, xarc 5; **mages: 2, both
in `cpk.rs`; `mages/convert.rs` has none**); conv-cli 2; conv-core 0.

Only a dry run catches what the whole corpus does (the Muramasa
collision above, effects past 255, a `?` in text), and only a full
build or a trace run catches assets and timing. Nothing checks that a
refactor left a game's `0.txt` alone.

Proposal (S):
- `tests/snapshot.sh`: for each game whose files are present
  (`$CONS_GAMES/<id>`, machine-local), run the dry run and
  compare the `0.txt` hash with `tests/snapshots/<game>.txt` (committed). Print
  only the games that changed, with the first differing lines. Each
  refactor step below runs it.
- A unit test per engine on a tiny synthetic input, without the game
  files: Nitroplus has the pattern (`Fake` assets, `LIBRARY`); add one
  for MAGES (a few tasks through `compile`) and for Xuse once it has an
  asset trait.
- A conv-cons test that builds one `Script` with every `Op` variant and
  every screen, emits it, runs `lint`, and checks the `alloc` ranges
  (finding 1), so a new `Op` can't silently break the define section.
- Trace baselines (`cons_trace_check.py --diff`) stay a manual step
  before merging a game to main: they need the full build.

| Change | Friction it removes | Cost |
|---|---|---|
